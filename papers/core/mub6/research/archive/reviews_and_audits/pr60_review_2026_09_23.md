## Findings and resulting behavior

- **P4 parameter-only certification was unsupported.** The original Python and
  Rust functions returned zero residuals without constructing a matrix. Their
  derivative polynomial had no connection to a supplied matrix family. Those
  entry points, including `build_matrix_residual_verifier`, now return a
  `MissingProofObligation` error. `compute_matrix_residual` instead computes
  every entry of `H H* - 6 I` from a supplied exact cyclotomic matrix. It does
  not check entry modulus, family membership, parameter binding, or derivatives.
  The Fourier fixture and its single-entry perturbation are checked in
  `test_supplied_fourier_matrix_and_perturbation` and Rust's
  `supplied_matrix_residual_and_perturbation`.
- **P4 interval arithmetic stays available without analytic promotion.** The
  separate interval API reuses the existing B1 receipt and auditor. Nonpositive
  radii, non-exact Python inputs, and empty mutated covers are rejected by the
  P4 regression controls. No new cover certificate or reflection claim is added.
- **Q3 discarded non-rational real components.** `cyc_real_rational` formerly
  returned only coefficient zero. It now requires that all other coefficients
  vanish. `test_nonrational_real_part_is_not_silently_truncated` checks a
  non-rational real cyclotomic input. An explicitly named coefficient projection
  remains available solely to explore the original proposed matrices.
- **Q3's proposed matrices lack a sound projector-moment interpretation.** For
  four copies of the standard basis, both proposed constructions admit the
  negative quadratic form recorded in
  `test_projector_consistency_counterexample_remains_visible`. These are actual
  projectors, not a mutually unbiased quadruple; the control addresses the
  proposed generic moment identities only. The moment builders and solver
  certification APIs now fail closed. Separate diagnostic APIs use schema
  `omega.mub.degree6-diagnostics.v2`, with `complete=false`,
  `moment_semantics_verified=false`, and both candidate-refutation flags false.
  `diagnostics_complete=true` refers only to the two constructed rational
  matrices and their exact trace/pivot calculations.
- **Python and Rust disagreed on matrix entries.** Rust used fixed cross-pair
  values, different triple diagonals, and omitted cross-triple terms. The
  diagnostic definitions now agree. Both test suites compare every entry via
  six canonical SHA-256 fingerprints in
  `tests/mub_verify/fixtures/pr60_degree6_diagnostics.json`. These fingerprints
  are regression data, not mathematical certificates.
- **Witness boundaries were unchecked.** Python and Rust now recheck witness
  dimensions, positive weights, input matrix dimensions and symmetry on every
  operation. Python rejects non-exact scalars. Mutation and singular-LDL
  regression controls exercise these checks.
- **Lean descriptions overstated the conclusions.** The new orbit lemmas
  specialize caller-supplied `AtlasCoversKnownModuli`. The theorem
  `MUB6.Gluing.ModuliReduction.concrete_moduli_to_covered_class_bridge` still
  requires catalog exhaustiveness and transition Hadamardness as hypotheses.
  `catalog_entries_land_in_covered_classes` has an existential triple conclusion.
  `MUB6.Gluing.TargetB1.anchor_ball_bounded_variation` unpacks parameter interval
  membership; it is not a matrix derivative estimate. The orthogonality wrapper
  uses the algebraic evidence already carried by each supplied point. Its type
  does not assert continuity or equality between the query parameter and the
  point's stored parameter. The documentation now states these limits.
