# Computation controls: composition and completed review

AuthorityEffect: None.

The six `comp-c2`, `comp-c3`, `comp-c6`, `comp-c7` and `comp-c8` scripts were
literal finite controls, not six independent computation engines. They are
composed into `checks/independent/comp-finite-model-controls.py`. The original
source bytes and complete companion histories are preserved in
`retired_computation_sources/`; the retirement manifest binds each old path to
its archive and replacement. Historical DAG/review citations remain historical.
The active regression harness and workflow now use the composed application.

## File decisions and delivered changes

The six retired executable files receive retention label **1** because their
behavior is incorporated into the application. Their old adjacent companion
paths receive **3**: preserved as referenced historical metadata in the archive,
with no claim that their old scores apply to a new source. Both new source files
and the changed `test_review_repairs.py` receive **5**, with completed **L4B**
assessments bound to their exact bytes. The new companions and mutation manifest
receive **5**. Label 5 is a retention decision, not a perfection claim.

This removes duplicate entry points and receipt scaffolding. It does not claim
a reduction in total line count: reusable validation, bounded certificate
search and independent verification add substantive behavior that the old
literal scripts did not provide. No empty compatibility wrappers remain.

`FiniteWordSystem` is the sole class in the application: a frozen aggregate
owning an alphabet and detached rule tuples. It validates symbol, shape,
duplicate, word-length and rule-count invariants. `apply` checks the exact
one-hole witness and the global 64-symbol limit; its output may exceed the
smaller search bound. Search and trace verification enforce that smaller bound.

Breadth-first search returns an owned shortest path or a proved negative for
the declared finite bounded graph. Its state and rule-offset budgets are
explicit and validated. The whole expansion cost is reserved before expansion;
exhaustion is a typed resource failure, never a successful negative answer.
The first discovery of the target returns immediately. Visited parents are
immutable within a search, including under cycles and identity rules.

Trace verification checks every step against the supplied rules. A repeated
word requires an actual self-step. It snapshots the caller's nested data,
rejects empty/out-of-bound traces and distinguishes a false witness from an
exhausted verification budget. Exact helpers reject bool/float and validate
ignored arguments; a halted writer preserves its existing value.

The six original controls execute **50** named obligations: 5 word-move,
5 no-rule-bound, 25 constant-writer, 6 encoding, 2 fixed-erasure and 7 tape
obligations. Counts come from actual `Cases` insertions. The combined receipt
and CLI preserve failures and invocation ownership. Expected failures use the
shared Railway boundary; unexpected programming errors and cancellation escape.

## Scope of the formal origins

All six original Lean modules were read and digest-bound in the requirements
map. C2 contains concrete one-hole word moves and a merge map. C3 uses a
one-symbol, no-rule system and a length-one bound. C6 is a constant writer with
halt persistence. C7's encoded reduction theorem has a supplied computability
premise; the Python pair predicate does not discharge it. The fixed-target
module contains two erasures, not the complete extended rule system. C8
constructs one marked tape, not a minimality theorem.

The new bounded graph API verifies exactly its declared finite relation. It
does not prove Genesis Step3 encoding, M0/Code.eval correspondence, an infinite
language reduction, the extended R0-prime construction or minimality. No new
Lean compilation, hosted CI or physical/continuum theorem is claimed.

## Verification and surviving evidence

The source-bound quality receipt records pinned strict mypy and normal/optimized
execution of 16 computation groups, 24 integration groups and 15 AdS groups
(including loader lifecycle challenges). Each generated property uses 80
deterministic cases. The independent oracle constructs graph edges by enumerating
left/right contexts, then computes distances by a layer fixed point. It shares
neither the production offset scan nor the predecessor queue. Explicit cases
check the oracle itself, shortest-path ordering, empty rules, insertion at the
final position, deletion, cycles, resource thresholds, ownership and refusal
helpers. The original independent integration oracles remain in place.

The initial 64-candidate mutation run detected **61** faults. Its selected tests
missed disabled rule matching, the wrong merge symbol and a reversed predicate
pair. Existing graph tests detect the first; the six fixed controls detect the
other two. The selectors were amended and those three candidates rerun, with
successful baselines. **64/64** eligible candidates are now detected. Source and
test bytes did not change during that closure; the initial manifest, all raw
outcomes and follow-up results are retained. No candidate was dropped or
declared equivalent to improve the rate.

The regression harness's population changes from 25 to 20 because six scripts
became one. Its shared-hole test loads that one application; the remaining
regression and loader code is unchanged. Its prior AdS assessment and mutation
evidence remain as historical evidence, with a new source-bound assessment and
fresh integrated runs for this migration. The source checkout is retested after
guarded synchronization; its receipt is a separate record.
